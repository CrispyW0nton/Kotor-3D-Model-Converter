## Current Product Shape

GhostRigger is now a hybrid Visual Studio C++ host plus embedded Python Qt
application. The product roadmap is organized around four authoring studios
over shared project, resource, validation, export, scene, and native-runtime
foundations:

1. **Character Studio:** import custom FBX/OBJ/glTF models, fit them to native
   KOTOR node hierarchies, bind/skin them, preview inherited or local
   animations, and export reloadable MDL/MDX plus install metadata.
2. **Retarget Studio:** retarget animation across KOTOR-to-KOTOR,
   KOTOR-to-Unreal, and Unreal/Mixamo-to-KOTOR with preview, readback, and
   export safety gates.
3. **Module Studio:** hydrate, inspect, edit, validate, and safely save KOTOR
   modules, including GFF-backed placed objects and walkmesh data.
4. **Map Studio:** author KMAP/KMAX-backed areas, room geometry, LYT/VIS/WOK,
   gameplay placements, package outputs, and game-test proof manifests.

## Evidence Snapshot

This revision is grounded in the repository as of 2026-06-21:

- Qt-only frontend remains the product direction; legacy Tk is retired and
  guarded by tests.
- The native host embeds Python in-process and the Visual Studio solution has
  been collapsed into canonical package owners: GUI Display, GUI Helpers, Qt,
  IO, Rendering, Resources, Scene, Tools, Workflow, Runtime Shared, Runtime
  Core, Native Core Foundation, Core Math, Project, Validation, Automation, and
  Bridge families.
- The native payload manifest currently covers 18 non-debug Python-payload DLL
  projects and 1,145 packaged Python file references. Regenerate payloads after
  canonical Python edits that are packaged into native DLLs.
- Shared suite foundations exist: `GhostRiggerProject`, `ResourceAddress`,
  `GameResourceProvider`, `ValidationBus`, `ExportJob`, provider-backed
  resource models, Character export transactions, and Map Studio package/proof
  tooling.
- Retarget Studio is the most advanced product lane. It has explicit modes,
  verified UE/Mixamo-to-KOTOR correction paths, KOTOR source sampling,
  KOTOR-to-Unreal export scaffolding, source/target selectors, readiness
  reporting, and many regression tests.
- Character Studio's biggest remaining risk is still native Odyssey DAG
  correctness: KOTOR animation binding depends on exact node names, parent
  chains, flags, hooks, bind data, and supermodel semantics.
- Module and Map backend services are strong, but the visible workflows still
  need consolidation, undo, shared resource browser integration, and game-proof
  polish.

## Current Critical Path

The shortest path to a credible modder beta is:

1. **Suite foundation productization:** ValidationBus issue panel, undo command
   foundation, shared job/progress bridge, and KMAX/KMAP/LYT/MDL/WOK transform
   contract.
2. **Character Studio native DAG lock:** snapshot a selected KOTOR base model,
   clone the DAG exactly, bind imported meshes without corrupting export nodes,
   and prove reload/animation inheritance.
3. **Retarget Studio parity:** bring KOTOR-to-KOTOR and KOTOR-to-Unreal up to
   the same preview/export/readback discipline as the verified
   Unreal/Mixamo-to-KOTOR lane.
4. **Map Studio proof:** finish the real `grdev01` game proof with recorded
   evidence, not just package and manifest readiness.
5. **Module/Map visible authoring:** make hydration, forms, WOK editing,
   placements, package output, and proof state feel like one coherent workflow.
6. **Regression and beta gates:** representative smoke tests, visual captures,
   export goldens, recovery, docs, and Windows packaging.

## Beta Definition

GhostRigger is ready for modder beta when all of the following are true:

- A user can import a custom character mesh, bind it to a native KOTOR node DAG,
  preview inherited/custom animations, export MDL/MDX, reload it, and stage
  install metadata.
- Retarget Studio supports KOTOR-to-KOTOR, KOTOR-to-Unreal, and
  Unreal/Mixamo-to-KOTOR with visible preview, export transactions, and readback
  or external validation.
- Module Studio can load a stock module, edit placed objects and walkmesh data,
  save safely, and reload the output.
- Map Studio can build a small custom area, author LYT/VIS/WOK and gameplay
  placements, package it as `.mod`, install or stage it, and record game proof.
- All four flows publish validation reports through one UI model and use
  transaction-style exports or package verification.
- Targeted backend checks and visible Debug-app workflow tests are recorded in
  `CHANGES.md`.
