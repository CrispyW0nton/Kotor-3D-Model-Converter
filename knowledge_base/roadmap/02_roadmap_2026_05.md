## M5 — Mode 1: Headless Body workflow  ✅ DONE

**Goal:** complete end-to-end the most common case — assemble + rig + validate + export a headless body.
**Commit:** `5a56dfd` (squashed). **PR #53 merged to `main` at `0fc07d7`.**

### Pattern established by M5 — reused throughout M6/M7/M8

The M5 milestone established the **canonical workflow-service pattern** that the remaining mode milestones replicate:

1. **Qt-free, pykotor-free service module** in `src/core/<mode>_workflow.py` — deferred imports via `_import_pykotor_model()` / `_import_<dep>()` helpers so the module loads under unit tests without optional deps.
2. **Per-step result dataclasses** with **structured codes** (e.g. `code in {clean, warnings_only, blocked}`) so the UI dispatches via codes, not error strings.
3. **`severity.value.lower()` pattern** in `_summarize_issues` — matches both real `Severity` enum and fakes injected via `monkeypatch`.
4. **Inspector page rewrite** retires every legacy `Open … Panel…` stub button with the real workflow UI.
5. **Window slot replacement** wires `_on_<step>_requested` to the workflow service.
6. **Fake-injection test pattern**: `monkeypatch.setattr(wf, "_import_<dep>", lambda: _FakeDep)` — runs tests without pykotor/PySide6.
7. **Commit per task ID**, squash to one milestone commit, PR per milestone.

All M6/M7/M8 tasks follow this template.

**Goal:** support the messy, varied world of KOTOR creatures — banthas, dewbacks, rancors, kinraths, jawas, droids — and the non-humanoid features they need (spines, tails, tentacles, wings).
**Revised effort:** ~7 dev-days (was 7-10). This is the **only milestone that's mostly greenfield**.
**Status:** 🔴 GREENFIELD (profile detector exists; rest is new code).

### Workflow steps (creature mode)

1. **Load Creature**
2. **Check Model** — non-strict (creatures don't need `headhook`/`talkdummy`)
3. **Profile Pick** — radio buttons: Humanoid / Quadruped / Multi-leg / Droid / Prop / Winged / Tentacled / Custom
4. **Limb Rig** — AcuRig profile guides for picked profile (uses existing `accurig.GuidePlacer`)
5. **Special Rigs** — sub-step appearing only for Winged / Tentacled / Multi-leg:
   - **Spline-IK** for tails/tentacles/spines (Stewart Jones §3, §4)
   - **Wing rig** with FLAP/FOLD/LINK/CTRL layered locators (§3)
   - **Tongue / mandible** sub-rig (single jaw bone + 4-bone tongue chain, §10)
6. **ROM Test** — auto-generated range-of-motion clip per profile (§9)
7. **Add Motions** — animation library filtered by creature supermodel
8. **Validate + Export**

## Rules of engagement (unchanged from original)

1. **Qt-only.** No new Tk code accepted; CI guard via `test_qt_only_imports.py`.
2. **Spec-first.** When a UI question is ambiguous, defer to `knowledge_base/reference/specs/character_builder_spec.md` then to the AccuRig HUD reference.
3. **Stewart Jones is the creature playbook.** The 3-Stage Asset Build (Base / Animation / Deformation), the naming convention, the spline-IK / wing / tail rig structures, and the ROM test methodology are non-negotiable for Mode 4.
4. **Validation gates export** — Errors block, Warnings prompt.
5. **Commit per task ID.** Every commit message references its `T###` ID from this roadmap.
6. **PR per milestone**, not per task. Squash all task commits within a milestone into one comprehensive commit before opening the PR (the M5 pattern; see PR #53).
7. **No new runtime dependencies** beyond PySide6, numpy, moderngl, Pillow. Dev-only `pytest-qt` + `pytest-image-snapshot` permitted for M11.
8. **Standing legacy-UI retirement directive** — every milestone removes any legacy `Open … Panel…` placeholder it encounters.
9. **Never push directly to `main`.** Branch is `qt-ghostrigger`; PR target is `main` (which since PR #52, #53 advanced past the original `defe7f8` pin — current `main` is whatever `origin/main` reports at PR time).

## What we're *not* doing in this roadmap

- No new arbitrary autorig (generic non-KOTOR pipelines). Mode 4 covers what KOTOR creatures need; everything else is out of scope.
- No new LIP authoring tool (we preview, we don't author). LIPs come from the classic KOTOR pipeline.
- No new physics simulation beyond the existing cloth/dangly module + M8/T804 mandible preset.
- No swap to a different render backend (we extend `qt_viewport.py` + ModernGL + `viewport_core.py`, no PyOpenGL refactor).
- No music / sound design — `qt_animation_panel.py` already covers audio playback.
- No new runtime deps. `pygltflib`, `pyassimp`, `pyfbx` rejected — in-tree writers cover all four formats.
