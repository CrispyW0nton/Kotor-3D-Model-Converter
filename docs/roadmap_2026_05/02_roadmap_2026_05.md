# GhostRigger Qt Roadmap — 2026-05 Edition

**Branch:** `qt-ghostrigger`
**Supersedes:** `.ghostrigger_reference/ROADMAP.md` (April 2026, pre-Qt)
**Companion doc:** [`01_qt_branch_audit.md`](./01_qt_branch_audit.md)
**Source material:** AccuRig HUD reference, facial rigging tutorial `pLRxzsPAqrE`,
Stewart Jones *Digital Creature Rigging: Wings, Tails & Tentacles* (CRC Press, 2019),
`.ghostrigger_reference/docs/character_builder_spec.md`.

---

## Headline goals

1. **Qt is the only supported front-end.** Tk is frozen and removed by M3.
2. **A real Character Builder window**, modeled on the AccuRig HUD, with **four model-type modes** matching KOTOR's actual asset classes: Headless Body, Head, Supermodel (Head + Headless composite), and Creature.
3. **A truthful viewport** with joint-dot HUD, mini-thumbnail inset, snap-views, and weight heat-map.
4. **A complete creature rigging path** — spline-IK chains, wing rigs, ROM tests — drawn from the Stewart Jones playbook.
5. **Validation banner + bottom strip** surfacing existing `validation_service.py` checks live as the user works.

## M5 — Mode 1: Headless Body workflow

**Goal:** complete end-to-end the most common case — assemble + rig + validate + export a headless body.

### Workflow steps (left rail)

1. **Load Body** — file dialog, accepts MDL/MDX/OBJ/FBX/glTF; auto-detects mode; rejects if not `HEADLESS_BODY` (offers correction)
2. **Check Model** — verify T-pose / A-pose, check scale (game units), verify `headhook` + `rhand` present, surface fixable issues in banner
3. **Body Rig** — AcuRig humanoid guides; mode-aware default pin positions; user adjusts via joint-dot HUD; **Generate Skeleton** button
4. **Hand Rig** — finger sub-mode; camera auto-zooms to hands; per-finger lock toggles for models missing digits
5. **Check Actor** — drop into a stock `walk` or `idle` animation from the Animation Library; visual ROM check
6. **Add Motions** — opens existing `qt_animation_panel.py` filtered to humanoid clips
7. **Validate + Export** — runs `validation_service.validate()`; on clean, opens export dialog (KOTOR / FBX / glTF / OBJ + sidecar JSON)

## M6 — Mode 2: Head workflow

**Goal:** end-to-end head rigging with facial bones, LIP preview, and viseme test. Replicates the bone hierarchy + workflow shown in the `pLRxzsPAqrE` facial tutorial.

### Workflow steps

1. **Load Head**
2. **Check Model** — assert `head_g`, `talkdummy`, `f_jaw_g`, `f_um_g`, `f_lmc_g`, `f_rmc_g`; flag missing
3. **Head Rig** — neck chain (3 joints: `necklwr_g`, `neck_g`, `Hturn_g`), `head_g` pivot at skull base, jaw at TMJ in front of tragus
4. **Face Rig** — eye bones, eyelid bones, lip-corner bones (`f_lmc_g`/`f_rmc_g`), upper-lip bone (`f_um_g`), brow bones if present
5. **LIP & Phoneme Test** — drives `LIPPlayback` from `character_builder.py` (already implemented); 16 KOTOR viseme buttons
6. **Check Face** — jaw open/close, blink L/R/both, smile, mouth-open, talk-loop preview (Stewart Jones validation poses)
7. **Validate + Export**

## M8 — Mode 4: Creature workflow (the Stewart Jones mode)

**Goal:** support the messy, varied world of KOTOR creatures — banthas, dewbacks, rancors, kinraths, jawas, droids — and the non-humanoid features they need (spines, tails, tentacles, wings).

### Workflow steps

1. **Load Creature**
2. **Check Model** — non-strict (creatures don't need `headhook`/`talkdummy`)
3. **Profile Pick** — radio buttons: Humanoid / Quadruped / Multi-leg (>4) / Droid / Prop / Winged / Tentacled / Custom
4. **Limb Rig** — AcuRig profile guides for picked profile
5. **Special Rigs** — sub-step that appears only for Winged / Tentacled / Multi-leg:
   - **Spline-IK** for tails/tentacles/spines (Stewart Jones §3, §4)
   - **Wing rig** with FLAP/FOLD/LINK/CTRL layered locators (§3 of book)
   - **Tongue / mandible** sub-rig for jaws (one bone for jaw + 4-bone tongue chain, per book §10)
6. **ROM Test** — auto-generated range-of-motion clip per profile (Stewart Jones §9)
7. **Add Motions** — animation library filtered by creature supermodel
8. **Validate + Export**

### Tasks

| ID | Task | Hours | Acceptance criteria |

| T801 | Profile-selector inspector page — radio buttons + thumbnail preview of guide layout | 3 | Switching profile re-populates guides |
| T802 | New `src/autorig/spline_ik.py` — fits a Catmull-Rom spline through a bone chain; exposes per-CV helpers; LookAt + path constraints; stretch factor as custom attribute | 10 | Unit-test against a 12-segment tail: end-effector follows spline within 1% |

## Rules of engagement

1. **Qt-only.** No new Tk code accepted; existing Tk modules are read-only references until M3.
2. **Spec-first.** When a UI question is ambiguous, defer to `.ghostrigger_reference/docs/character_builder_spec.md` then to the AccuRig HUD reference.
3. **Stewart Jones is the creature playbook.** The 3-Stage Asset Build (Base / Animation / Deformation), the naming convention, the spline-IK / wing / tail rig structures, and the ROM test methodology are non-negotiable for Mode 4.
4. **Validation gates export** — Errors block, Warnings prompt.
5. **Commit per task ID.** Every commit message references its `T###` ID from this roadmap.
6. **PR per milestone**, not per task. Squash tasks within a milestone into one comprehensive commit before opening the PR.
7. **No new dependencies** beyond PySide6, numpy, moderngl, Pillow, and what's already in `requirements.txt`.

## What we're *not* doing in this roadmap

- No new arbitrary autorig (generic non-KOTOR pipelines). Mode 4 covers what KOTOR creatures need; everything else is out of scope.
- No new LIP authoring tool (we preview, we don't author). LIPs come from the classic KOTOR pipeline.
- No new physics simulation beyond the existing cloth/dangly module.
- No swap to a different render backend (we extend `qt_viewport.py` + ModernGL, no PyOpenGL refactor).
- No music / sound design — `qt_animation_panel.py` already covers audio playback.
