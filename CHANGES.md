## 2026-05-21

- Added theme-specific Matrix bar colours and a dedicated `matrix` font role. All packaged themes now define `matrixBar.*` colour tokens matched to their palette, and the Matrix bar font defaults to the bundled `Aurebesh AF` font while remaining editable in the Theme Editor Fonts tab. No roadmap task ID applies.
  Follow-up: gave the header IPC status label its own `HeaderIpcMeta` object name and verified it resolves through `matrixBar.ipcText` for every packaged theme instead of inheriting the generic header meta colour.
  Follow-up: fixed the crash reported in `logs/ghostrigger_2026-05-21_135423.log`; the Matrix bar painter now passes `QtGui.QFont.Weight` enum values to `QFont.setWeight()` instead of raw integers, which PySide6 rejected during repaint.
  Follow-up: compacted the Settings dialog by splitting it into top-level tabs for Paths, General, Matrix Bar, Theme/Layout, and Measurement, with scrollable tab pages and two-row action grids so hidden sections no longer force a huge window size.
  Follow-up: fixed Settings dialog theme application so Apply Theme targets and repaints the dialog itself instead of disabling the parent main window updates, preventing the settings window from visually disappearing until resize.
  Follow-up: polished the Theme Editor metric tables. Theme and layout metrics now hide row numbers, use bold label widgets inside metric cells, use spin-box value editors with explicit unit suffixes, and include tab width/padding/margin metrics in both fallback tokens and packaged layout XML. Layout application and preview now understand the new tab sizing tokens.
  Follow-up: lowered the default tab height to 14 px and added theme-controlled tab style modes. Themes now load/save `<styles><style name="tab.mode" value="standard|flat|beveled"/></styles>`, the Theme Editor exposes a tab style mode selector, and the stylesheet builder renders standard, flat, and beveled tab treatments.
  Follow-up: refined collapsible tool sections. The shared `CollapsibleGroupBox` expander is now a fixed square control that ignores global button minimum sizes, reserves stable header space, restores expanded geometry, and collapses to a fixed header height. Mesh Tools now top-aligns sections with stretch only after the final group so collapsed sections stack from top to bottom.
  Follow-up: made Settings dialog Apply Theme persist immediately by emitting the normal settings payload after a successful apply, so the chosen theme is written to `settings.json` and no longer reverts to the previously saved Classic selection on restart.
  Follow-up: made Theme Editor Apply Theme persist through the main window settings writer as well. Theme/layout settings now merge with theme-owned fields applied after layout-owned fields so stale layout-manager data cannot overwrite the selected theme.
  Follow-up: moved theme stylesheet generation onto a worker `QThread` and added theme-apply progress signals. The main window now shows the themed progress toast during theme application, updates it while the background stylesheet build runs, and keeps it visible before the unavoidable main-thread Qt widget restyle step.
  Follow-up: moved the viewport mode toolbar out of the viewport widget and into a shell-owned toolbar band below the main command bar. The same viewport buttons are reparented into the new band, while side spacers track the left and right panel widths so the strip sits in the central space above the viewport column.
  Follow-up: changed the Output Log title from a clickable tool button into a plain themed section label inside the log pane, matching the Python terminal presentation. Both Output Log and Python section labels now use stylesheet tokens for monospace title styling.
  Follow-up: added the startup-console look as a packaged `Droid` theme. The new `config/themes/themes/droid.xml` uses dark graphite panels, grey controls, high-contrast text, Matrix-green accents, matching Matrix bar tokens, and the bundled Aurebesh Matrix font. Docs and theme-loading tests now list Droid as a built-in default theme.
  Follow-up: moved the header, command bar, and viewport toolbar into a non-movable reserved top `QToolBar` so the viewport tool strip sits directly under Open/Auto-Rig/Character Builder and Qt docks cannot occupy the top UI area. Detachable/toolbox docks now explicitly disallow the top dock area and are redirected back to workspace side areas if needed.
  Follow-up: replaced the reserved top area's horizontal scroll strips with wrapping flow layouts. At the default window width, command buttons and viewport controls now wrap onto left-aligned rows underneath instead of clipping or requiring a horizontal scrollbar; layout application no longer forces those wrapping rows back to a single fixed height.
  Follow-up: added a built-in `Default` native theme. `config/themes/themes/default.xml` sets `application.native=true`, causing the stylesheet builder to return no QSS and the theme applier to restore the platform Qt palette instead of applying GhostRigger font/palette overrides. Applying Default clears local GhostRigger styles and disables the Matrix bar animation so the app can be inspected with plain platform styling.
  Follow-up: fixed the gimbal crash caused by a renderer instance missing `show_gimbal`. The viewport now initializes that compatibility flag, all gimbal hover/toggle/draw paths use a defensive accessor, and the CPU base-render suppression path preserves/restores the visible gimbal state instead of converting a missing attribute into "gimbal off."
  Follow-up: restored the visible model transform gimbal after the compatibility fix. The viewport now falls back to the loaded model root if selection state is dropped, positions the root gimbal at the model bounds center like the previous renderer path, and feeds the overlay gizmo from the active theme gimbal colours.
  Follow-up: fixed the Default native theme viewport regression where the advanced transform gizmo, corner axes gimbal, and HUD stats disappeared. `FrameRenderer` now initializes render/overlay runtime state before any theme hook runs, theme colour application no longer resets animation/gimbal/walkmesh state, and native theme application resets viewport/GPU colours without requiring QSS.
  Follow-up: tied the native Default look into the viewport renderer itself. Default/native mode now derives the CPU canvas, HUD pills, grid lines, gimbal highlight text, GPU clear colour, GPU grid colours, and GPU wire colour from the active Qt palette instead of falling back to GhostRigger's dark renderer palette.
  Follow-up: restored native-style contrast for themed spin-box steppers. All custom themes now define editable `spinbox.*` colour tokens for the up/down button fill, hover, pressed, border, and arrow colours, and the generated QSS draws bordered stepper containers for `QSpinBox` and `QDoubleSpinBox` instead of leaving them visually flat against the field.
  Follow-up: replaced the QSS triangle arrows with explicit light/dark SVG arrow assets for spin-box steppers, fixing the themed up/down controls that were rendering square blocks instead of arrows.
  Follow-up: added startup theme stylesheet precaching before the Qt main-window launch. `ThemeApplier` now shares a process-wide stylesheet cache, and `main.py` prints per-theme precache progress plus a summary to the launching terminal so later theme switches use warmed stylesheets immediately.
  Follow-up: fixed collapsible tool-section expanders so they stay small square controls instead of inheriting global command-button sizing. The shared `CollapsibleGroupBox` toggle now opts out of layout button-mode sizing and the generated theme QSS includes a dedicated fixed-size selector for `QToolButton#CollapsibleGroupToggle`.
  Follow-up: moved Matrix bar controls out of Settings and into the Theme Editor. Matrix bar mode, glyphs, font override, and PNG/GIF path are now theme `<styles>` entries (`matrixBar.style`, `matrixBar.glyphs`, `matrixBar.fontFamily`, `matrixBar.imagePath`), while older app-level Matrix bar settings remain a fallback for existing user configs.
  Follow-up: fixed Default/native theme Matrix bar images. Native theme application now honors the active theme's Matrix bar config instead of forcing Matrix panels disabled, and the Theme Editor Matrix Bar preview renders selected PNG/GIF media instead of always showing the glyph strip.
  Follow-up: limited Matrix bar media to the top header only. The command bar is a normal themed frame again, Matrix media rendering now supports percentage crop rectangles, and the Theme Editor preview includes a bounded, scaled image selector so large source images no longer force the editor window oversized.
  Follow-up: adjusted the Matrix Bar image preview into a fixed-height source-image box with a crop rectangle overlay. The preview displays the full source image scaled into the box, the crop rectangle defines the Matrix bar slice, and the media no longer resizes the Theme Editor window.
